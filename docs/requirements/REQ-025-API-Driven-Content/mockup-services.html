📐 Mockup-Spezifikation für die Implementierung

  • Cards: entsprechen Tags aus /api/v1/branches/{id}/categories (sortiert nach rank). Title = tag.name. Anzahl unter dem Title = Anzahl Operations mit diesem Tag.
  • Sub-Options: Operations aus /api/v1/branches/{id}/operations, gefiltert auf operation.tagIds.includes(tag.id), sortiert nach operation.order.
  • Service-Beschreibung (Punkt b Iter. 3): operation.description direkt unter dem Operation-Namen, in der Klasse service-card__option-desc — Schriftgröße var(--font-size-sm), Farbe var(--color-text-secondary), mit line-clamp: 3 und Einrückung links via margin-left: 1.85em. Wenn description == null → keine Description-Zeile.
  • Multi-Tag-Operations: Operations können in mehreren Tags auftauchen (z.B. „Hol & Bringservice" hat alle 7 Tags) und erscheinen daher in jeder zugehörigen Card. Spiegelt die SoftNet-Pflege wider.
  • Variant-Detection (TireChange): Tag mit rank === 3 (= „Räderwechsel"). Frontend markiert selectedVariant === 'tireChange', sobald eine Operation mit diesem Tag selektiert wird.
  • Icons: Aktuell Material-Icon-Fallback (Emoji-Platzhalter im Mockup). Wenn SoftNet später imageId nutzbar macht, via /api/planning/images/{id} auflösen.
  • Responsive: 4 Spalten Desktop (≥ 64em), 2 Spalten Tablet (≥ 36em), 1 Spalte Mobile.
  • BEM: Block .service-card, Modifier --selected/--expanded, Element __icon/__title/__count/__options/__option/__option-row/__option-name/__option-desc/__actions.
